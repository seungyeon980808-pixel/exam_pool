## 1. 제품 개요

### 한 줄 요약
ExamPool을 "문항 은행"에서 "출제 지휘소"로 확장한다 — 교사는 세트 청사진(구성 계획)만 짜고, 문항 텍스트·그림·HWP 조판은 Claude Code가 5E·ExamPool·hwpPalette를 부려서 완성한다. 사람의 역할은 출제가 아니라 검토다.

### 해결하는 문제
출제의 4대 고통 중 3개(이미지 생성 → 5E, 레퍼런스 체크 → ExamPool, HWP 조판 → hwpPalette)는 이미 도구화됐다. 남은 문제는 두 가지:
1. **세트 구성** — "이번 시험을 어떤 유형·주제·배점 조합으로 짤 것인가"를 도와주는 도구가 없다 (유일하게 도구가 없는 고통).
2. **파이프라인 단절** — 세 도구 사이 9개 갭(그림 파일 자동 저장 없음, 문항 쓰기 MCP 없음, HWP 완전 수동 등) 때문에 매 구간 사람이 손으로 나른다.

### 핵심 가치
- 새 앱을 짓지 않는다. **ExamPool이 ExamMaker로 성장**한다 — exam_set 테이블, SQLite, MCP 서버, hwpPalette 마크다운 변환기를 전부 재사용.
- AI 엔진은 **Claude Code 세션** — 앱에는 LLM도 API 키도 없다(ExamPool 설계 원칙 유지). 5E MCP·ExamPool MCP·그림 자가검증 루프를 그대로 쓴다.
- 모든 문항은 **근거(evidence) 링크 필수** — 성취기준·교과서 인용이 붙은 문항만 생성되므로, 검토가 "읽고 판단"으로 끝난다.

## 2. 사용자

### 주요 사용자
- **누구**: 박승연 (서울 대왕중 과학교사) 본인 전용
- **상황**: 정기고사·수행평가 출제 기간, 자택/학교 PC (Windows + 한컴오피스 + Claude Code 구독)
- **목표**: 프롬프트 몇 줄로 정확한 시험 문항 세트를 생성하고, 검토만 하고, 버튼/명령 하나로 HWP 시험지를 얻는다

### 사용자 시나리오 (목표 흐름)
1. ExamPool 웹 화면에서 **세트 청사진**을 짠다 — 슬롯마다 유형(정답형/합답형/서술형/실험형)·주제(성취기준)·배점·부정발문 여부·그림 필요 여부를 클릭으로 지정하고, 필요한 슬롯에 상황 묘사를 적는다.
2. **"출제 지시문 복사"** 버튼 → Claude Code 세션(32_exam_pool 폴더에서 시작)에 붙여넣는다.
3. Claude가 슬롯별로: `search_evidence`로 근거 수집 → 명제·오답 변형 생성 → **문항 조립(신규 쓰기 MCP)** → 그림이 필요하면 5E로 그리고 **자동 저장(신규 save_image)** → `material`에 파일명 기록.
4. 교사는 웹 화면에서 문항·근거·그림을 검토한다. 그림이 마음에 안 들면 5E에서 해당 페이지를 고치고 다시 저장 → 파일명이 같으므로 자동 반영.
5. 세트 확정 → **hwpPalette CLI 한 줄**로 한글이 열리며 세트 전체가 조판된다. 최종 확인 후 사용자가 저장.

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름
```
청사진 작성(웹) → 지시문 복사 → Claude Code 생성(텍스트+그림) → 웹에서 검토·수정 → 세트 확정 → CLI 조판 → 한글에서 최종 확인·저장
```

### 상세 흐름
1. **청사진 작성**: 세트 화면의 "계획" 탭에서 슬롯 추가. 슬롯마다 유형·성취기준(기존 seed 활용)·배점·부정발문·그림 여부 선택, 상황 묘사 입력. 배점 합계·유형 분포가 상단에 실시간 표시.
2. **지시문 복사**: 버튼 하나로 "슬롯별 요구사항 + MCP 사용 규약 + 파일명 규약"이 담긴 지시문이 클립보드로. (Claude Code 프롬프트 규칙에 따라 한국어+영어 병기)
3. **AI 생성**: Claude가 슬롯 순회 — 근거 검색 → 명제/변형 → 문항 생성(쓰기 MCP) → 그림 필요 시 5E 규약(그리기→export_image 자가검증→save_image) → material 기록 → 슬롯에 연결.
4. **검토**: 웹 화면에서 문항 텍스트·선지·근거 인용·그림을 확인. 수정은 웹 UI 직접 편집 또는 Claude에게 재지시. 그림 수정은 5E에서 페이지 열어 고친 뒤 같은 파일명으로 재저장.
5. **조판**: 세트 확정 → export API가 마크다운 파일 생성 → `hwp_palette CLI` 실행 → 한글이 열리고 세트 전체 조판. **저장은 사용자 손으로** (5E와 같은 철학).

## 5. 성공 기준

- [ ] 청사진 작성부터 HWP 조판 완료까지 **사람의 복사·붙여넣기·클릭이 5회 이하** (현재: 문항당 수십 회)
- [ ] 20문항 세트 기준, 그림 파일을 손으로 옮기는 횟수 **0회**
- [ ] 생성된 모든 선다형 문항에 근거(evidence) 1개 이상 자동 연결
- [ ] 서술형·정답형+사진·비실험 합답형이 `_fallback_text` 없이 정식 템플릿으로 조판됨
- [ ] 기존 ExamPool 단독 사용(문항 은행·수동 조립)이 깨지지 않음

## 6. 안 만드는 것 (Out of Scope)

> 이 목록에 있는 건 Phase 1에서 만들지 않습니다.

- **새 저장소/새 앱** — 이유: ExamPool 확장으로 결정됨. 5E·hwpPalette는 각자 저장소에서 최소 수정만.
- **앱 내장 LLM / API 키** — 이유: Claude Code 세션이 엔진. ExamPool "LLM 없음" 원칙 유지.
- **hwpPalette 완전 MCP화** — 이유: COM 자동화 MCP는 비용 대비 위험이 크고 검토만 된 상태. Phase 3 후보.
- **화면의 진짜 "생성 버튼"(헤드리스 실행)** — 이유: 진행 표시·에러 처리 부담. Phase 3에서 `claude -p` 방식 재검토.
- **문항 난이도 자동 추정·통계** — 이유: MVP는 생성 파이프라인 완결이 우선.
- **다중 사용자·공유 기능** — 이유: 본인 전용 로컬 도구.
