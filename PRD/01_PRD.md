## 1. 제품 개요

### 한 줄 요약
수업·교과서에서 나온 **참인 명제를 근거와 함께 아카이브**하고, 그 명제들을 조합해 **모든 선지가 근거를 가진 시험 문항 세트**를 설계한 뒤 hwppalette 문법으로 출력하는 로컬 프로그램.

### 해결하는 문제
시험 출제의 3요소(내용 + 이미지 + 편집) 중 이미지는 5E, 편집은 hwppalette로 해결했다. 남은 것이 **내용**이다. 현재는:
- 선지 하나하나가 교과서에 있는지, 성취기준 안인지 **매번 PDF를 뒤지며 확인** (최대 고통)
- 참/거짓 명제(특히 매력적인 오답)를 매번 새로 짜내며 **아이디어 고갈**
- 복수정답·오류 시비가 무서워 **체계 없는 눈검토를 반복**

### 핵심 가치
**근거 있는 출제.** 세트의 모든 선지가 "성취기준 + 교과서 원문 인용(또는 수업 기록)"과 연결된 상태로 완성된다. 민원·오류 시비가 왔을 때 클릭 한 번으로 근거를 제시할 수 있고, 출제 자체도 축적된 명제 은행에서 조합하는 작업이 된다.

## 2. 사용자

### 주요 사용자
- **누구**: 박승연 (중학교 과학교사) — 단일 사용자, 로컬 사용
- **상황**: 상시(수업 후 명제 축적) + 시험기간(문항·세트 설계)
- **목표**: 근거가 완비된 시험 문항 세트를 빠르고 불안 없이 완성

### 사용자 시나리오
1. 수업 후, 클로바노트 녹취 텍스트를 붙여넣고 그날 다룬 내용 중 시험에 쓸 참 명제를 골라 저장한다 (성취기준·단원 분류 + 교과서 근거 연결)
2. 시험기간, 세트를 만들고 성취기준별로 명제를 골라 문항(발문+보기+선지)을 조립한다
3. 자동 체크리스트를 통과시킨 뒤 세트 전체를 hwppalette 문법으로 클립보드에 복사 → 한글에서 Ctrl+T로 조판 완료

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름
```
[축적] 수업/교과서 → 명제 등록(분류+근거) → 오답 변형 저장
[설계] 세트 생성 → 은행에서 명제 선택 → 문항 조립 → 검토(자동 체크리스트) → 배열·배점 확정
[출력] hwppalette 문법 복사 → 한글 붙여넣기 → Ctrl+T → 조판 완료
```

### 상세 흐름
1. **명제 등록**: 텍스트 입력 → 성취기준 선택(내장 목록) → 단원·학습목표·태그 → 근거(출처+원문 인용) 첨부
2. **오답 만들기**: 참 명제 상세에서 "변형 추가" → 왜곡 유형 선택 → 거짓 문장 작성 (근거 = 원본 참 명제)
3. **문항 조립**: 유형 선택 → 발문 작성(서식 명령 `\굵게{옳지 않은}` 그대로 사용 가능) → 보기/선지 슬롯에 명제 드래그 또는 직접 작성(직접 작성 시 근거 입력 요구) → 정답·배점·난이도·출제의도
4. **세트 설계**: 은행에서 문항 담기 → 드래그로 순서 변경 → 상단에 배점 합·난이도 분포·성취기준 커버리지 실시간 표시
5. **검토**: 자동 체크리스트 통과 확인 → 문항별 "근거 보기" 버튼으로 성취기준+원문 최종 확인 → (필요시) 인쇄용 검토본 출력
6. **출력**: "hwppalette로 복사" → 한글에서 붙여넣고 Ctrl+T

## 5. 디자인 방향

**나이스(NEIS)/K-에듀파인 업무포털의 디자인 언어를 따른다** (사용자 결정 2026-07-22). 교사가 매일 쓰는 인터페이스라 학습 곡선이 없고, 나이스의 "조회 필터 + 결과 테이블 + 합계 바" 패턴이 명제 은행·문항 관리에 그대로 맞기 때문.

**핵심 패턴 (나이스 "개인근무상황관리"에서 차용)**
- **조회 화면 골격**: 상단 조회 필터 바(라벨+입력+파란 조회 버튼) → 도구 버튼 줄(엑셀·등록·액션, 우측 정렬) → 결과 테이블 → 하단 진회색 합계 바
- **카드형 대신 테이블형**: 명제 은행은 밀도 높은 조회 테이블(성취기준·명제·단원·근거·변형·수업 컬럼). 다중 선택·엑셀 내려받기 지원
- **좌측 트리 메뉴**: 성취기준·단원 트리 + 보기 필터 (나이스 좌측 기본 메뉴 스타일)

**색·형태**
- 진파랑 헤더 `#2f5fa6`, 파란 주요/조회 버튼 `#2f6ac0`, 초록 엑셀 버튼 `#3c9d5a`, 회색 테이블 헤더 `#eef2f7`, 진회색 합계 바 `#6b7684`, 얇은 회색 테두리 `#d5dce6`
- 각진 모서리(border-radius 3~4px), 흰/연회색 줄무늬 행, 파란 원문자 ①②③, 빨강은 필수·경고용
- AI티 금지(그라데이션·큰 그림자·emoji)는 나이스도 동일 — 자연히 충족
- 본문 폰트는 나이스와 동일하게 시스템 산세리프(맑은 고딕 계열), 코드/문법은 IBM Plex Mono
- 데스크톱 우선 (학교 PC 전용 — 모바일 시나리오 없음)

> ExamPool 목업(나이스 스타일 명제 은행)은 2026-07-22 대화에서 확인. 5E·hwppalette의 기존 GitHub 톤(#0969da)과는 다른 방향이지만, "교사에게 익숙한 업무 도구"라는 성격상 나이스 언어가 더 적합하다고 판단.

## 6. 성공 기준

- [ ] 실제 시험 1회(중간 or 기말)를 이 프로그램으로 설계해 hwppalette 출력까지 완주
- [ ] 세트의 모든 선지에서 "근거 보기" 클릭 시 성취기준 + 원문 인용이 표시됨
- [ ] 명제 100개 이상 축적 시에도 검색·필터가 즉각 반응 (SQLite 전문 검색)
- [ ] 출력물을 한글에 붙여넣고 Ctrl+T 했을 때 수정 없이 조판됨 (hwppalette 문법 100% 호환)
- [ ] 교과서·교육과정 PDF 폴더 인덱싱 후 키워드 검색으로 근거 문단을 2초 이내에 찾을 수 있음 (2026-07-22 실측: 606페이지 인덱싱 7.9초, 검색 2ms 이하 — 검증 완료)

## 7. 안 만드는 것 (Out of Scope)

- **AI 연동(API·복붙 중계 모두)** — 이유: 분석 결과 AI 필수 지점이 없음. 근거 확인은 FTS5 검색, 오답은 왜곡 유형 프리셋, 선지는 프리셋 버튼, 검토는 규칙 체크리스트로 전부 해결. 실제 사용 후 필요성이 확인되면 그때 추가 검토 (미래 옵션으로 보류)
- **서술형·서답형 문항** — 이유: 문항 유형에서 제외(정답형·합답형 2종). 모범답안·채점기준 모델이 커서 후순위
- **클라우드 동기화·다중 기기** — 이유: 시험 자료 보안. 학교 PC 단독 + 파일 백업
- **다중 사용자·로그인** — 이유: 단일 사용자 로컬 도구. 인증 자체가 없음
- **한글(HWP) 직접 조판** — 이유: 조판은 hwppalette의 역할. 이 프로그램은 문법 텍스트 생성까지만 (느슨한 결합)
- **음성 파일 업로드·자체 STT** — 이유: 클로바노트 복붙 방식 채택. 비용·복잡도 회피
- **이미지 제작·편집** — 이유: 5E의 역할. 여기서는 파일 참조만
