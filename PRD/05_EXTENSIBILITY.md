# ExamPool — 다른 과목 확장성 검토

> 검토·검증일: 2026-07-22
> 질문: "다른 과목 선생님도 동일하게 사용할 수 있는가?"
> **결론: 가능하다. 성취기준 seed 파일만 교체하면 된다. 코드 수정 불필요.**

---

## 1. 검증 방법 (말이 아니라 실측)

국어·영어 성취기준 seed를 실제로 만들어 적재하고, 명제→문항→선지→출력→검토까지 돌려봤다.

| 검증 항목 | 국어 | 영어 |
|---|---|---|
| 성취기준 seed 적재 (`[9국01-01]`, `[9영01-01]`) | ✅ | ✅ |
| 명제–단원–성취기준 조인 | ✅ | ✅ |
| hwppalette 출력 변환 | ✅ | ✅ |
| 자동 검토 체크리스트 | ✅ | ✅ |

**코드 내 `9과` 하드코딩 점검**: 실제 로직에는 없음. 추출 도구(`tools/extract_standards.py`)의 도움말 문자열에만 예시로 등장한다 → **과목 중립**.

---

## 2. 다른 과목 선생님이 쓰는 방법

### 1단계 — 자기 과목 성취기준 뽑기
```bash
python tools/extract_standards.py "국어과 교육과정.pdf" \
  --prefix 9국 \
  --subject "중학교 국어 (2022 개정)" \
  --start "[중학교 1~3학년]" --end "선택 중심 교육과정" \
  --out app/seed/standards.json
```
- `--prefix`: 성취기준 코드 접두사. 문서에서 `[9국01-01]` 같은 코드를 찾아 `9국` 부분을 넣는다
- 2022 개정 교육과정 문서는 과목이 달라도 편집 형식이 같아서(단원 헤더 `(1) 이름` + 성취기준 `[코드]`) 대체로 그대로 동작한다
- 실행하면 단원별 개수가 출력된다. **반드시 눈으로 검수할 것** (줄바꿈으로 단어가 쪼개지는 경우가 있다 — 과학에서도 14곳 있었다)

### 2단계 — DB 초기화 후 실행
```bash
del data\exam_pool.db     # 기존 DB 삭제 (첫 실행 시 seed 자동 적재)
run.bat
```
상단 바에 `중학교 국어 (2022 개정) · 성취기준 N개`가 뜨면 성공.

### 3단계 — 자기 교과서 인덱싱
`근거 문서` 탭 → 교과서 PDF가 있는 폴더 지정 → 인덱싱. 이후 근거 검색이 자기 과목 교과서에서 이뤄진다.

## 3. 과목이 바뀌어도 그대로인 것 / 손봐야 하는 것

### 그대로 (수정 불필요)
- **데이터 구조 전체** — 명제·거짓변형·근거·문항·선지·세트 (과목 무관한 평가 개념)
- **문항 유형** 정답형·합답형, 부정 발문 토글 — 모든 선택형 과목 공통
- **합답형 프리셋** A/B/C — 수능 전 과목이 같은 조합 패턴을 쓴다
- **근거 검색** — PDF 텍스트 검색이라 과목 무관
- **hwppalette 출력** — 조판 문법은 과목과 무관
- **검토 체크리스트** — 근거 없는 선지·정답 미지정·배점 불일치는 모든 과목 공통

### 과목별로 다를 수 있는 것
| 항목 | 현재 | 다른 과목이면 |
|---|---|---|
| 성취기준 seed | 중학교 과학 87개 | 추출 도구로 교체 (위 1단계) |
| 학년군 표기 | "중학교 1~3학년" | `--grade-band` 로 지정 |
| 보기 라벨 | ㄱ ㄴ ㄷ ㄹ ㅁ | 그대로 쓸 수 있음 (전 과목 관행) |
| 배점 목표 | 100점 | 세트 검토 시 `target` 파라미터로 조정 |

### 지금은 안 되는 것 (한계)
- **한 DB에 여러 과목 동시 운용** — 현재는 한 번에 한 과목. 과목을 바꾸려면 DB를 새로 만든다.
  여러 과목을 병행하려면 폴더를 복사해 각각 쓰는 것이 가장 간단하다.
  (구조상 `standard` 테이블에 `subject` 컬럼을 넣으면 확장 가능하지만, 단일 사용자 도구라 지금은 과잉 설계로 판단)
- **국어 지문형 문항** — 긴 제시문(비문학 지문 등)은 `지문` 필드에 들어가지만, 한 지문에 여러 문항이 딸리는
  **세트형 문항(1지문 3문항)** 구조는 아직 없다. 국어·영어에서 흔한 형태라 필요하면 Phase 2 후보.
- **서술형** — 유형에서 제외한 상태 (모범답안·채점기준 모델 없음)

---

## 4. 배포 시 고려사항

- 다른 선생님 PC에는 **Python 설치**가 필요하다. 부담되면 hwppalette처럼 PyInstaller로 exe 패키징 가능(안정화 후 검토)
- 시험 데이터(`data/`)는 각자 PC에만 있고 외부 전송이 없다 — 여러 교사가 써도 서로 데이터가 섞이지 않는다
- `app/seed/standards.json`을 과목별로 만들어 배포하면 각자 자기 과목으로 시작할 수 있다
