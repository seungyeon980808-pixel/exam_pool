# ExamPool — 데이터 모델

> 앱에서 다루는 핵심 데이터의 구조. 개발자가 아니어도 이해할 수 있는 "개념적 ERD".
> 저장소: 로컬 SQLite 파일 1개 (`exam_pool.db`)

---

## 전체 구조

```
[성취기준] --1:N--> [명제] --1:N--> [거짓 변형]
   |                  |
   |                  └--1:N--> [근거]
   |
[단원] / [학습목표]  (명제의 분류 축)

[명제·변형] --N:M--> [선지] --N:1--> [문항] --N:M--> [세트]
                                       |               (SetItem: 순서·배점)
                                       └--1:N--> [보기항목]
        문항 부분: 지문 · 자료 · 발문 · 보기 · 선지 (학계 표준 용어)

[문서] --1:N--> [문서페이지]   (Phase 1: PDF 폴더 인덱스, SQLite FTS5 검색 → 근거 연결)
[수업기록]                      (Phase 2: 클로바노트 녹취 → 같은 FTS5 인덱스)
```

핵심은 **명제 → 문항 → 세트의 3층 구조**다. 명제는 재료, 문항은 조립품, 세트는 배치다. 내년에 같은 단원을 출제할 때 아래층(명제·문항)이 그대로 재산이 된다.

## 엔티티 상세

### Standard (성취기준) — 내장 데이터
2022 개정 중학교 과학 성취기준(교육부 고시 제2022-33호 [별책 9] '공통 교육과정')에서 **직접 추출·검증 완료**. 23개 단원, 87개 성취기준 전체가 `app/seed/standards.json`에 있으며 첫 실행 시 DB에 적재된다.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| code | 성취기준 코드 (PK) | [9과10-01] | O |
| grade_band | 학년군 (교육과정 원문 그대로 — 학년별로 나뉘지 않음) | 중학교 1~3학년 | O |
| unit_no | 소속 단원 번호(1~23) | 10 | O |
| seq | 단원 내 순번 | 1 | O |
| text | 성취기준 전문 | 빛의 반사와 굴절의 원리를 이해하고, 물체를 보는 과정을 빛의 경로를 이용하여 표현할 수 있다. | O |

> 2022 개정 중학교 과학 교육과정은 성취기준을 학년별(1/2/3학년)로 나누지 않고 "중학교 1~3학년" 학년군 전체로 제시한다. 학교별·교사별로 학년에 배분하므로, "이 성취기준을 몇 학년에서 가르치는가"는 이 앱이 정하지 않고 사용자가 명제·단원 태그로 관리한다.

### Unit (단원) / Objective (학습목표)
| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| unit_no | 단원 번호(1~23, 교육과정 원문 순서) | 10 | O |
| name | 단원명 (교육과정 원문) | 빛과 파동 | O |
| Objective.id | 학습목표 고유 식별자 | o-21 | O |
| Objective.text | 학습목표 (사용자 정의) | "굴절 현상을 설명할 수 있다" | O |
| Objective.standard_code | 소속 성취기준 | [9과10-01] | O |

단원은 성취기준과 함께 교육과정 원문에서 그대로 가져온 고정 목록(23개)이고, 학습목표는 사용자가 직접 등록한다(수업 설계 용어와 일치시키기 위해).

| text | 명제 본문 | 빛의 속력은 매질마다 다르다 | O |

### FalseVariant (거짓 변형) — 오답 선지의 재료
참 명제에 **종속**된다. 오답의 근거 = 원본 참 명제.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 식별자 | v-0290 | O |
| proposition_id | 원본 참 명제 | p-0132 | O |
| text | 거짓 문장 | 빛의 속력은 모든 매질에서 같다 | O |
| distortion | 왜곡 유형 | 수치·정도 변경 / 주체 바꿈 / 인과 역전 / 조건 삭제 / 개념 혼동 | O |
| note | 매력도 메모 | 굴절 학습 전 오개념과 일치 | X |

### Evidence (근거) — 명제 1개에 여러 개 가능
| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 식별자 | e-0410 | O |
| proposition_id | 대상 명제 | p-0132 | O |
| source_type | 출처 종류 | 교과서 / 교육과정 해설 / 수업 / 기타 | O |
| source_label | 출처 표기 | 미래엔 과학2 p.132 | O |
| quote | 원문 인용 | "빛은 매질에 따라 진행 속력이 달라지며…" | O |
| document_page_id | 인덱스된 페이지 연결 (Phase 1) | → DocumentPage | X |
| lesson_id | 수업 기록 연결 (Phase 3) | → Lesson | X |

MVP부터 PDF 검색 결과를 드래그하면 source_label + quote + document_page_id가 자동 채워진다(수정 가능). 검색으로 못 찾은 경우엔 손으로 입력. **근거 연결이 AI 없이 검색만으로 되므로, 남은 조건(수업 언급 여부)도 Phase 2에서 같은 검색 방식(lesson_id 연결)으로 처리된다.**

### Question (문항)

문항 부분 명칭은 **교육평가 학계 표준 용어**를 따른다(2026-07-22 리서치로 검증). 순서: 지문 → 자료 → 발문 → 보기 → 선지.

| 필드 | 명칭 | 설명 | 예시 | 필수 |
|------|------|------|------|------|
| id | | 고유 식별자 | q-0034 | O |
| qtype | 유형 | **정답형 / 합답형** 2종 | 합답형 | O |
| is_negative | 부정 발문 | 발문을 "옳은 것"→"옳지 않은 것"으로 (별도 유형 아님, 토글) | false | O |
| passage | **지문** | 도입 설명문 | 다음은 전자기 유도에 대한 설명이다. | X |
| material | **자료** | 그림·표: 텍스트 또는 이미지 파일명(hwppalette `\파일이름\`) | fig_refraction_01 | X |
| ask | **발문** | 실제 물음 (hwppalette 서식 명령 포함 가능) | 옳은 것만을 \<보기\>에서 있는 대로 고른 것은? | O |
| bogi_items | **보기** | 합답형일 때 ㄱ.ㄴ.ㄷ. 문장(각각 명제/변형 연결) | [{label:ㄱ, text, prop_ref}] | X |
| answer | 정답 | 선지 번호 | ③ | O |
| default_points | 기본 배점 | | 3.0 | O |
| difficulty | 난이도 | 상 / 중 / 하 | 중 | O |
| standard_code | 성취기준 | 대표 성취기준 | [9과10-01] | O |
| intent | 출제 의도 | 출제 의도·고려사항 | 오개념(속력 불변) 판별 | X |
| status | 상태 | 초안 / 검토중 / 확정 | 초안 | O |
| review_note | 검토 기록 | 자동 체크리스트 결과·수동 메모 | JSON | X |

> **부정형을 유형에서 뺀 이유**: 부정형은 정답형·합답형 어느 쪽에도 붙을 수 있는 발문의 변형일 뿐(옳은 것↔옳지 않은 것)이다. 별도 유형으로 두면 조합이 4개(정답×2, 합답×2)로 늘지만, `is_negative` 토글 하나로 처리하면 유형은 2개로 유지되고 hwppalette 출력 시 발문의 "옳지 않은"에 자동으로 서식 강조(`\굵게{옳지 않은}`)를 넣을 수 있다. (사용자 결정)

### Choice (선지) — 문항 1개에 5개
| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 식별자 | c-0201 | O |
| question_id | 소속 문항 | q-0034 | O |
| order | 번호(①~⑤) | 1~5 | O |
| text | 선지 본문 (정답형: 명제/변형 문장 / 합답형: ㄱ,ㄷ 같은 보기 조합) | 빛의 속력은 모든 매질에서 같다 / ㄱ, ㄷ | O |
| proposition_id | 참 명제 연결 (정답형) | p-0132 | X |
| variant_id | 거짓 변형 연결 (정답형) | v-0290 | X |
| combo | 보기 조합 (합답형) | ["ㄱ","ㄷ"] | X |
| custom_evidence | 직접 작성 선지의 근거 (연결 없을 때 필수 요구) | {source_label, quote} | X |
| is_answer | 정답 여부 | true | O |

**규칙: 정답형 선지는 proposition_id, variant_id, custom_evidence 중 하나를 반드시 가진다.** 합답형은 combo가 가리키는 보기 항목들이 각자 명제/변형 근거를 갖는다. 이것이 "근거 있는 출제"를 데이터 구조로 강제하는 지점이며, 검토 체크리스트의 1번 검사 항목이다.

### 합답형 선지 프리셋 (5개년 수능 + 평가원 연수자료 실측)
합답형은 선지를 손으로 짜지 않고 **프리셋 버튼**으로 생성한다. 보기 ㄱㄴㄷ를 쓰고 정답 조합을 정한 뒤 프리셋을 고르면 5개 선지가 자동 생성된다. 2022~2026 수능 물리학Ⅰ 74개 합답형 블록 분석 결과 아래 2개가 90%(67/74):

| 프리셋 | ① | ② | ③ | ④ | ⑤ | 실측 |
|--------|----|----|----|----|----|------|
| **A** | ㄱ | ㄴ | ㄱ,ㄷ | ㄴ,ㄷ | ㄱ,ㄴ,ㄷ | 34회 |
| **B** | ㄱ | ㄷ | ㄱ,ㄴ | ㄴ,ㄷ | ㄱ,ㄴ,ㄷ | 33회 |
| C | ㄴ | ㄷ | ㄱ,ㄴ | ㄱ,ㄷ | ㄱ,ㄴ,ㄷ | 변형 |

공통 규칙: ⑤는 항상 ㄱㄴㄷ, ④는 대개 ㄴㄷ. 프리셋 선택 후에도 개별 수정 가능. (선택지 수가 다른 과탐형 세트 — PPT 슬라이드 59의 "과탐(물리학)에서 사용" 세트와 일치)

### ExamSet (세트) / SetItem (세트 구성)
| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id / name | 세트 이름 | 2026-2학기 중간 (2학년) | O |
| status | 상태 | 설계중 / 완성 | O |
| SetItem.question_id | 담긴 문항 | q-0034 | O |
| SetItem.order | 배열 순서 (드래그로 변경) | 7 | O |
| SetItem.points | 이 세트에서의 배점 (기본값 덮어쓰기 가능) | 4.5 | O |

세트 화면 상단 대시보드는 SetItem을 집계해 **배점 합·난이도 분포·성취기준 커버리지**를 실시간 계산한다 (별도 저장 없음 — 항상 파생).

### Document / DocumentPage (Phase 1 — 근거 검색용 PDF 인덱스) · Lesson (Phase 3)
| 엔티티 | 필드 요약 |
|--------|-----------|
| Document | id, title(파일명에서 추출, 예: "중_과학2(정대홍)_교과서"), doc_type(교과서/교육과정), file_path, indexed_at |
| DocumentPage | id, document_id, page_no, text (PyMuPDF 추출 텍스트), FTS5 가상 테이블에 별도 색인 |
| Lesson | id, date, class_name(2-3), transcript(클로바노트 텍스트), summary |

**실측 검증 완료 (2026-07-22)**: 교과서 326페이지 + 교육과정 280페이지 → 인덱싱 7.9초, 키워드 검색 2ms 이하(SQLite FTS5 `bm25()` 랭킹). "빛의 굴절" 검색 시 교과서 103쪽의 단원 학습목표 문장이 최상위로 정확히 매칭됨. 폴더 지정 방식(하위 폴더 재귀 스캔)으로 DocFinder와 동일한 UX를 AI 없이 재현.

Evidence 엔티티의 `document_page_id`는 이 DocumentPage와 연결되며, 근거 입력 화면에서 검색 결과를 드래그하면 `source_label`(파일명 + 페이지) + `quote`(검색된 문단, 필요시 수정)가 자동 채워진다.

## 왜 이 구조인가

- **명제/변형 분리**: 거짓 문장을 독립 저장하면 "왜 거짓인가"의 근거가 끊긴다. 원본 참 명제에 묶으면 방어 논리가 자동으로 따라온다 (인터뷰 확정)
- **선지의 3중 근거 규칙**: "근거 있는 출제"라는 핵심 가치를 UI 권장이 아니라 **데이터 제약**으로 만든다. 근거 없는 선지는 체크리스트를 통과할 수 없다
- **문항 은행 ↔ 세트 분리**: 내년 재출제 시 문항을 복사 없이 재사용·변형. 배점은 SetItem에 두어 같은 문항을 세트마다 다른 배점으로 쓸 수 있다
- **문서 인덱스를 Phase 1로 당김**: PDF 검색은 AI 없이 SQLite FTS5만으로 충분히 빠르고 정확함이 실측으로 확인됐다(2026-07-22). 근거 확인이 출제 과정 최대 고통이었으므로, 자동화 가능한 부분을 뒤로 미룰 이유가 없었다
- **확장성**: Phase 3(수업기록)은 Evidence의 빈 연결 필드(`lesson_id`)를 채우는 방식이라 **기존 스키마를 바꾸지 않는다**
- **단순성**: 사용자 계정·권한·동기화 테이블이 없다. 단일 사용자 로컬 도구이기 때문
