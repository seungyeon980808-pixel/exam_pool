## Phase 1: MVP — 명제→문항→출력 코어 (+ PDF 근거 검색)

### 목표
**실제 시험 1회를 이 프로그램으로 설계해 hwppalette 출력까지 완주할 수 있다.**
"모든 선지에 근거"라는 핵심 가치는 첫 버전부터 강제되고, 근거 확인(출제 최대 고통)은 AI 없이 PDF 검색으로 자동화된다 — 2026-07-22 실측으로 타당성 검증 완료(교과서 326p+교육과정 280p 인덱싱 7.9초, 검색 2ms 이하).

### 기능
- [ ] SQLite 스키마 + 성취기준 내장 데이터 적재 (`app/seed/standards.json` — 2022 개정 중학교 과학 23단원 87개, 이미 추출 완료)
- [ ] PDF 폴더 인덱싱: 폴더 지정 → 하위 폴더 재귀 스캔 → PyMuPDF로 페이지별 텍스트 추출 → SQLite FTS5 색인. 재색인 버튼
- [ ] 근거 검색: 명제/근거 입력 화면에 검색창 → 일치율(BM25) 순 페이지 목록 + 스니펫 → 드래그로 근거 저장(출처·원문 자동 입력, 수정 가능)
- [ ] 명제 CRUD: 등록·검색(전문 검색)·필터(성취기준/단원/태그)
- [ ] 거짓 변형 등록 (왜곡 유형 5종)
- [ ] 문항 조립: 5지선다 / ㄱㄴㄷ합답형 / 자료제시형 — 명제 드래그 배치 + 직접 작성(근거 요구)
- [ ] 문항 은행 목록 + 세트 관리: 드래그 배열, 배점 합·난이도 분포·성취기준 커버리지 대시보드
- [ ] 자동 체크리스트: 근거 없는 선지 / 정답 미지정 / 배점 불일치 / 커버리지 공백
- [ ] hwppalette 문법 출력 → 클립보드 복사
- [ ] 롤링 백업 (.bak1~3)

### 데이터
- Standard, Unit, Objective, Proposition, FalseVariant, Evidence, Question, Choice, ExamSet, SetItem, **Document, DocumentPage**
- Lesson은 **스키마만 만들어두고 화면 없음** (Phase 2에서 채움 — Document와 같은 인덱스 구조라 확장 쉬움)

### 인증
- 없음 (단일 사용자 로컬 도구)

### "진짜 제품" 체크리스트 (로컬 도구 기준으로 조정)
- [ ] 실제 SQLite 파일에 저장 (메모리·목업 X)
- [ ] run.bat 더블클릭 → 브라우저 자동 오픈까지 동작
- [ ] hwppalette 실기 검증: 출력물을 한글에 붙여 Ctrl+T → 수정 없이 조판됨
- [ ] 명제 200개를 넣고 검색·필터 반응 속도 확인
- [ ] 실제 교과서·교육과정 PDF 폴더로 인덱싱 → 검색 → 드래그 근거 저장까지 한 번에 동작 (2026-07-22 스크립트 단위 검증 완료, 앱 UI에 통합해 재검증)

## Phase 2: 수업 녹취 아카이브 — 근거 검색의 확장

### 전제 조건
- Phase 1으로 실제 시험 1회 완주, 불편 지점 목록 확보

### 목표
출제 조건 2번("수업에서 언급했는가")을 기록으로 답한다. 별도 AI 없이, **Phase 1의 PDF 근거 검색과 똑같은 FTS5 인덱스**에 수업 기록을 얹으면 된다.

### 기능
- [ ] 수업 기록 등록: 클로바노트 텍스트 복붙 + 날짜·반 태그
- [ ] 수업 기록을 문서 인덱스에 포함 → 근거 검색창에서 교과서·교육과정과 함께 검색됨 (출처 종류만 "수업"으로 구분)
- [ ] 명제에 "수업 근거" 연결 시 `class_verified` 자동 표시 + 수업 일자·발언 인용 저장
- [ ] 근거 검색 결과에서 출처 종류 필터(교과서 / 교육과정 / 수업)

### 통합 테스트
- 수업 기록이 Phase 1의 교과서 검색과 한 화면에서 함께 검색되는지
- 수업 텍스트는 로컬에만 저장 — 외부 전송 없음(학생 발언 포함 가능성 대비)

## AI 연동 — 보류 (미래 옵션)

원래 Phase 2로 계획했던 AI(명제 추출·오답 초안·검토 의견)는 **분석 결과 필수 지점이 없어 기획에서 제외**했다(2026-07-22 결정). 근거 확인=FTS5 검색, 오답=왜곡 유형 프리셋, 선지=프리셋 버튼, 검토=규칙 체크리스트로 전부 해결된다.

실제 사용 후 "오답 아이디어가 정말 고갈된다"거나 "의미적 검토가 꼭 필요하다"가 확인되면, 그때 **복붙 중계 방식**(프롬프트를 클립보드에 만들어주고 사용자가 Claude에 붙여넣기)으로 추가 검토한다. API 직접 호출은 비용·키 관리·보안 부담 대비 이득이 없어 계획하지 않는다.
